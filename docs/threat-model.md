# Pocket Agent Host Threat Model

## Purpose and scope

Pocket Agent Host converts an owner-managed Android device into a private, long-running Hermes host. This document distinguishes **enforced controls** from operating assumptions so that the product never represents an unverified safeguard as a guarantee. The scope is the shipped Android app, its embedded worker, its owner-only Telegram gateway, and its configured model endpoint.

## Assets, trust boundaries, and actors

| Asset or boundary | Primary risk | Implemented control | Remaining owner responsibility |
|---|---|---|---|
| Telegram bot token and model credential | Credential disclosure or reuse | Android Keystore-backed handoff and deletion through the native supervisor; redacted diagnostics | Use a dedicated bot and revoke credentials if the device is compromised. |
| Private owner identity | Unauthorized instruction or group routing | A single private numeric owner identity; group and allow-all gateway routes are cleared before polling | Confirm the chat identifier belongs to the owner before enabling the host. |
| Task, schedule, and run data | Local disclosure or uncontrolled execution | App-private storage, bounded history, serial task drain, cron validation, bounded retries | Do not schedule sensitive tasks on a device shared with untrusted people. |
| Device availability and host resource use | Battery depletion, storage exhaustion, sustained host CPU/RAM use, restart loops | Charging/storage start gates, owner-selected bounded CPU/process-RAM/private-workspace guardrails, owner-configurable visual near-limit alerts, a volatile bounded dashboard chart, owner-reviewed hardware-aware recommendations, boot opt-in, foreground service, bounded recovery, local alerts | Keep the host charged, unlocked as required by the OS, and choose limits compatible with the selected model workload and phone capacity. |
| Model endpoint | Prompt or output disclosure in transit | HTTPS-only model configuration and Android-side preflight | Select a model provider whose retention and data policies meet the owner’s requirements. |
| Owner-session context metadata and compression | Transcript disclosure through the UI, unsafe concurrent mutation, or a misleading success claim | The bridge exports numeric token-window metadata only; a guarded single compression request targets the canonical owner session, waits for active work to finish, and reports failure without changing the conversation | Treat provider-created compression summaries as model-provider data and select a provider whose retention policy is acceptable. |
| Remote MCP endpoint and tool manifest | Malicious endpoint, credential leakage, unapproved side effect, or private-network targeting | HTTPS-only policy; blocked local/private targets and redirects; protected credential handoff; manifest fingerprinting; explicit expiring owner grants | Select servers whose privacy, retention, and tool behavior are acceptable, and review each tool before granting it. |
| Owner-approved code transformation | Model-generated JavaScript reads credentials, reaches the network, escapes to a shell, or consumes uncontrolled resources | Source-built QuickJS core runs only in a non-exported Android isolated process; the parent verifies a short-lived SHA-256 approval, and the evaluator denies imports and exposes no host APIs while enforcing time, heap, stack, IPC, source, and output bounds | Review each source hash before approval. This is a capability-free data-transformation tier, not a terminal, package runtime, or general VPS. |

## Threat scenarios

| Scenario | Security outcome | Mitigation status |
|---|---|---|
| A stranger messages the bot or adds it to a group | The request must not become a task | **Enforced:** the worker configures one owner and removes group/allow-all routes before gateway start. |
| A physical attacker opens the host app | Secrets must not be rendered or copied from diagnostics | **Partially enforced:** secrets are held in protected storage and native diagnostics are redacted. Device screen-lock and encryption remain OS-owner controls. |
| A gateway exits repeatedly | The phone must not consume resources in an infinite restart loop | **Enforced:** recovery is cooldown-controlled and capped. |
| Storage or power falls below policy | New host work must not begin in an unsafe state | **Enforced:** the same saved policy is applied to direct starts, restart recovery, and boot restoration. |
| The host process exceeds an owner resource guardrail | The agent must not keep consuming app-private storage, process RAM, or sustained CPU without owner intervention | **Enforced within the app boundary:** the worker refuses new task/schedule persistence when the private workspace quota is full; the Android supervisor stops the host for private-workspace or process-RAM breaches and after repeated CPU samples above the configured threshold. Android does not provide this app with device-wide CPU cgroups or a hard memory reservation. |
| The host is approaching an owner resource guardrail | The owner needs a clear opportunity to adjust work or limits before enforced host stop | **Visible when native data is present:** The owner chooses an integer warning percentage from 50–90% and a higher critical percentage up to 99%; defaults are 80% and 95%. Dashboard and Settings apply those thresholds to CPU, process-RAM, and private-workspace limits. These are display-only indicators; Android remains the enforcement authority. |
| A resource chart exposes durable or broader device telemetry | A local diagnostic feature could leak unnecessary historical data | **Bounded:** The dashboard retains at most 30 in-memory 12-second samples for the active app session. It represents CPU, process RAM, and the app-private workspace quota only; it does not scan unrelated device storage and does not persist chart samples into tasks, diagnostics, or analytics. |
| An owner applies a recommended limit to an underpowered or shared phone | A convenience action could over-allocate device capacity | **Partially enforced:** the action uses Android-reported CPU cores, total RAM, free storage, and the owner’s storage reserve to fill conservative bounded values, but does not save or start the host automatically. The owner reviews and saves the settings. |
| A model provider endpoint is mistyped or unavailable | The owner must see failure before the Telegram host begins | **Enforced:** Android-native preflight validates the HTTPS endpoint, model name, and credential without persisting an exposed value. |
| An owner requests context compression while a task is active, or Hermes cannot compact safely | The current session must not be concurrently rewritten or silently discarded | **Enforced:** the native bridge blocks concurrent requests, checks for an active owner turn, uses Hermes' supported `/compress` path, and reports failure without modifying the existing conversation. The UI receives numeric context metadata only, not the transcript. |
| An MCP server advertises a new, changed, or deceptive tool | A server response must not become tool authorization | **Enforced:** discovery normalizes untrusted metadata; a manifest change invalidates grants; invocation requires a matching enabled connector and unexpired owner approval. |
| An MCP endpoint directly names a local or private address | The agent must not become a private-network request proxy | **Enforced:** both the TypeScript discovery client and embedded worker reject non-HTTPS, loopback, private, link-local, reserved, IPv6, URL-credential, redirected, and non-standard-port destinations. DNS hostnames remain an owner-selected external-service boundary. |
| A reviewed code job attempts to loop forever, allocate memory, import a module, or access the host | The job must end without receiving device permissions, credentials, filesystem access, or a general process capability | **Enforced within the Android app boundary:** each run creates a fresh QuickJS runtime in an `isolatedProcess` service; the JNI evaluator sets memory and stack limits, installs a wall-clock interrupt, rejects all module imports, and never registers `std`, `os`, filesystem, network, process, or Android callbacks. The main process requires an enabled policy and an unexpired SHA-256 source approval before binding to the service. |

## Non-goals and explicit limits

Pocket Agent Host is not a general-purpose remote shell, a mobile-device-management system, a container runtime, or a guarantee that Android will keep a process alive under every OEM power policy. Its owner resource settings supervise the single app process and app-private runtime directory; they are not a root-level device governor, a CPU cgroup, or a hard Android memory allocator. It deliberately exposes no terminal interface, browser automation, arbitrary command execution, local/`stdio` MCP server transport, or public inbound HTTP server. The optional isolated JavaScript card is restricted to individually owner-approved, capability-free in-memory transformations; it is not a terminal, Node.js runtime, package manager, filesystem, or network client. The app does not provide end-to-end encryption beyond the configured external services; Telegram, the chosen model provider, and owner-selected MCP servers each have their own data-handling model.

## Security release gate

Before a public release, maintainers must verify the app lock screen behavior on a real device, validate restricted owner access from a non-owner Telegram account and group, test credential rotation/deletion, and review every `manual-review` license finding in `license-audit.json`. The implementation map in [implementation-traceability-matrix.md](./implementation-traceability-matrix.md) identifies the source contract and acceptance evidence for each control.
